# F4.3: User login and access tokens

## Summary

F4.3 completes sign-in for ViganGo. Users log in with email and password, or sign in with Google, and receive a short-lived JWT access token. The token is sent as `Authorization: Bearer <access_token>` to protected endpoints such as `GET /api/v1/auth/me`.

## Endpoints

| Method | Endpoint              | Success                    | Failures                                                    |
| ------ | --------------------- | -------------------------- | ----------------------------------------------------------- |
| `POST` | `/api/v1/auth/login`  | **200** profile + token    | **401** bad credentials, **422** invalid input, **503** JWT unconfigured |
| `POST` | `/api/v1/auth/google` | **201** new / **200** returning user, profile + token | **401**, **409**, **422**, **503** (see F4.2 and README) |
| `GET`  | `/api/v1/auth/me`     | **200** profile            | **401** missing/invalid/expired token, **503** JWT unconfigured |

Login and Google sign-in response (`AuthResponse`):

```json
{
  "id": "6f1c2a3e-0000-4000-8000-000000000000",
  "username": "traveler",
  "email": "traveler@example.com",
  "image_url": null,
  "access_token": "<jwt>",
  "token_type": "bearer"
}
```

`AuthResponse` extends `UserResponse`, so the profile fields match `/register` and `/me`. Adding the token to `/google` and the profile to `/login` only added fields; no existing field was removed or renamed.

## How it works

| File                            | Responsibility                                                                 |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `app/services/login.py`         | Finds the account by case-insensitive email and verifies the Argon2id hash.    |
| `app/services/tokens.py`        | Signs and verifies HS256 JWTs (`sub`, `iss`, `aud`, `iat`, `nbf`, `exp`, `token_type`). |
| `app/services/current_user.py`  | `get_current_user` dependency: reads the bearer token and loads the user.      |
| `app/routers/auth.py`           | `create_auth_response` builds the profile + token response for `/login` and `/google`. |
| `app/schemas/auth.py`           | `LoginRequest` and `AuthResponse`.                                             |

## Security decisions

- **Generic failures:** unknown email, wrong password, and Google-only accounts all return the same **401** message, so the response does not reveal which emails are registered.
- **Constant work on failure:** when no local password exists, login still verifies a placeholder Argon2 hash, so response time does not reveal registered emails either.
- **Short-lived tokens:** access tokens expire after 15 minutes and are rejected if the signature, issuer, audience, expiry, or token type is wrong.
- **Secret handling:** `JWT_SECRET_KEY` must be at least 32 bytes and is read from the environment. If it is missing, token endpoints return **503** and never issue a token.
- **Deleted accounts:** a valid token for a user that no longer exists returns **401** from `/me`.

## Testing

`tests/conftest.py` sets a test-only `JWT_SECRET_KEY` for every test. With the disposable PostgreSQL container from [F4.2](f4.2-user-registration.md#isolated-postgresql-test-setup) running:

```bash
TEST_DATABASE_URL='postgresql+psycopg://vigango_test:local_only_password@127.0.0.1:55432/vigango_test' \
python -m pytest -v -ra
```

Result on this branch: **82 passed** with PostgreSQL; **65 passed, 17 skipped** without `TEST_DATABASE_URL`.

| Area             | Tests                                                                                     |
| ---------------- | ----------------------------------------------------------------------------------------- |
| Login service    | Valid password, wrong password, unknown account, Google-only account, placeholder hash check |
| Login endpoint   | Profile + token response, token opens `/me`, generic 401s, no token on failure, 422 payloads, 503 without key |
| Google sign-in   | New and returning users receive a valid token; 503 without key                            |
| Tokens and `/me` | Expired, tampered, wrong audience/issuer/type, missing header, wrong scheme, deleted account |
| PostgreSQL       | Register → login → `/me`; Google sign-in → `/me`; wrong password; case-variant email     |

## Not included

- Refresh tokens and logout (clients sign in again after 15 minutes).
- Rate limiting or lockout for repeated failed logins.
- Linking a Google account to an existing email/password account.
